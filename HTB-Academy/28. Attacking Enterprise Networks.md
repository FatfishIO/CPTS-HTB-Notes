## Scenario & Kickoff

| **Category** | **Details** |
|---|---|
| **Scenario — overview** | Client **Inlanefreight** has contracted **Acme Security, Ltd.** to perform a full-scope External Penetration Test to assess perimeter security; customer asked to identify as many vulnerabilities as possible; therefore, evasive testing is not required; would like to see what sort of access can be achieved by an anonymous user on the Internet; per the Rules of Engagement (RoE), if we can breach the DMZ and gain a foothold into the internal network, they would like us to see how far we can take that access, up to and including Active Directory domain compromise; client has not provided web application, VPN, or Active Directory user credentials |
| **Scope — External Testing** | `10.129.x.x` ("external" facing target host); `*.inlanefreight.local` (all subdomains); `INLANEFREIGHT.LOCAL` (Active Directory domain) |
| **Scope — Internal Testing** | `172.16.8.0/23`; `172.16.9.0/23` |
| **Scope — additional notes** | Customer provided the primary domain and internal networks but has not given specifics on the exact subdomains within this scope nor the "live" hosts that will be encountered within the network; would like us to perform discovery to see what type of visibility an attacker can gain against their external network (and internal if a foothold is achieved) |
| **Scope — permitted testing** | Automated testing techniques such as enumeration and vulnerability scanning are permitted, but must work carefully not to cause any service disruptions |
| **Out of scope** | Phishing/Social Engineering against any Inlanefreight employees or customers; Physical attacks against Inlanefreight facilities; Destructive actions or Denial of Service (DoS) testing; Modifications to the environment without written consent from authorized Inlanefreight IT staff |
| **Project Kickoff — SoW and RoE** | At this point, have a **Scope of Work (SoW)** signed by both company management and an authorized member of the Inlanefreight IT department; SoW lists the specifics of testing, methodology, timeline, and agreed-upon meetings and deliverables; client also signed a separate **Rules of Engagement (RoE)** document, commonly known as an **Authorization to Test** document; crucial to have in hand before beginning testing and lists out the scope for all assessment types (URLs, individual IP addresses, CIDR network ranges, and credentials, if applicable); also lists key personnel from the testing company and Inlanefreight (a minimum of two contacts for each side, including their cell phone number and email address); document also lists out specifics such as testing start and stop date, and the allowed testing window |
| **Project Kickoff — timeline** | Given **one week** for testing and **two additional days** to write the draft report (which should be worked on as we go); client authorized to test 24/7 but asked to run any heavy vulnerability scans outside regular business hours (after **18:00 London time**); checked all necessary documents and have the required signatures from both sides, and the scope is filled in entirely, so good to go from an administrative perspective |
| **Start of Testing** | First thing Monday morning, ready to begin testing; testing VM is set up and ready to go, and a skeleton notetaking and directory structure has been set up to take notes using the favorite notetaking tool; while initial discovery scans run, as always, will fill in as much of the report template as possible — one small efficiency that can be gained while waiting for scans to complete to optimize the time available for testing; drafted the following email to signal the start of testing and copied all necessary personnel: `Email from Bryan Robinson to Sarah McDonald about the start of an external penetration test for Inlanefreight. Testing traffic from IP 10.10.14.15. Secondary contact: John Lee, Principal Security Consultant. Includes contact details and testing procedure overview.`; click send on the email and kick off external information gathering |
